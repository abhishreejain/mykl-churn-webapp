# FINAL_OUTPUT_TO_DASHBOARD_NOTE

Date: 2026-05-22

## Source of Dashboard Truth

Dashboard payload is built from the final enriched output generated by:

- `scripts/add_potential_to_scored_file.py`

Final file used:

- `backend/runtime/jobs/{job_id}/output/final_enriched_output.csv`

## Backend Mapping Logic

Dashboard builder:

- `mykl_churn_webapp/backend/app/services/dashboard_service.py`

Config-driven mapping:

- `mykl_churn_webapp/frontend/ui_bucket_config.json`

Used for:

1. `Potential Band -> Potential Level`
2. `Risk x Potential Level -> Priority Bucket (RED/ORANGE/GREEN/OTHER)`

Any unmapped combination is explicitly routed to `OTHER` and reported in warnings.

## Dashboard Response Contents

`GET /api/dashboard/{job_id}` returns:

- `priority_bucket_counts` (`RED`, `ORANGE`, `GREEN`, `OTHER`)
- `state_list`
- `risk_list`
- `potential_level_list`
- `counts_by_state`
- `counts_by_risk`
- `counts_by_potential_level`
- `influencer_records` (derived from final enriched output rows)

## Frontend Binding

Frontend flow in `frontend/app.js`:

1. Upload file
2. Process job
3. Fetch dashboard JSON
4. Render right-panel cards/filters/list from returned JSON

This replaces static placeholders with real output-derived content after successful processing.
